# Cyberpunk 2077 Co-op: свой NightCoop Hub на VPS

GameHub управляет хабом NightCoop: поиском сессий, согласованием прямых соединений и запасной ретрансляцией. Сам Cyberpunk 2077 работает у игроков, один из них держит игровую сессию. Это не автономный сервер игрового мира. Нужен совместимый мод NightCoop на каждом игровом ПК; игровые файлы в GameHub не входят.

## Установка

1. Подготовьте VPS x86_64 с Ubuntu 24.04+ или Debian 13+. Нужен g++ 13+; штатного компилятора Debian 12 недостаточно. ARM и Windows-сборка NightCoop в GameHub пока не поддерживаются.
2. Установите GameHub по [инструкции выделенной панели](DEDICATED.md). Например, `sudo bash scripts/install-server.sh auto`; вместо `auto` можно указать порт панели. Установщик добавит gcc/g++ и службу от отдельного пользователя. Сохраните выданные логин, пароль и отпечаток TLS.
3. Откройте HTTPS-панель, выберите **Cyberpunk 2077 Co-op**, создайте экземпляр. Укажите внешний домен или IPv4 VPS без схемы и порта. Для небольшого VPS начните с одного потока; автоматический режим берёт ядра ОС и может не учитывать квоту виртуального CPU.
4. Нажмите **«Установить NightCoop автоматически»**. GameHub скачает закреплённые исходники хаба и ENet, соберёт родной бинарник и создаст собственный ключ. Docker и ручной выбор архива не нужны. Сборка требует памяти и может занять несколько минут; сообщение об ошибке компилятора появится в статусе установки.
5. Во вкладке **NightCoop** проверьте UDP-порты и адрес с отпечатком, выполните диагностику и запустите хаб. Проверяйте готовность в консоли.

## Порты

HTTPS-порт панели и игровые UDP-порты независимы. Разрешите доступ к панели в firewall VPS/провайдера только нужным пользователям; для игроков нужны все UDP-порты, показанные вкладкой NightCoop. GameHub сам firewall не меняет.

При входном порте `47800`: один поток использует UDP `47800`; четыре — `47800`, `47810`, `47811`, `47812`. Общая формула: первый поток — входной порт, последующие — входной порт + 9 + номер потока, нумерация с нуля. Игровой TCP не нужен. Для примера с четырьмя потоками в UFW: `sudo ufw allow 47800/udp` и `sudo ufw allow 47810:47812/udp`. Не включайте UFW вслепую на удалённой машине: сохраните доступ SSH.

Для нестандартного порта строка подключения имеет вид `hub.example.org:48000#XXXX-XXXX-XXXX-XXXX`. Вкладка формирует её автоматически; вместо шаблонного адреса задайте реальный внешний адрес VPS.

## Подключение и настройки

В игровом меню NightCoop: **Совместная игра → Сервер → Добавить свой сервер**, вставьте адрес с отпечатком. Хост создаёт сессию и передаёт гостю приглашение. Сам мод ограничивает игровую сессию хостом и семью гостями; параметры ёмкости хаба этот лимит не увеличивают. Подключение с внешней сети и игровой процесс проверяются отдельно.

Во вкладке «Настройки» доступны все рабочие параметры родного хаба: потоки, соединения/сессии/гости, лимит по адресу, размер пакета, idle timeout, статистика, cookie и порог нагрузки, guard и пул памяти, очередь, UDP receive buffer, возобновление сессий, регион, собственные имена, файловый журнал, время работы и режим нагрузочного теста. «Все параметры» редактирует тот же проверяемый `nightcoop.json`. Сначала остановите экземпляр. Явный интервал статистики включает её также без активности — так работает родной параметр `--stats`.

Настройка receive buffer ограничена Linux `net.core.rmem_max`: GameHub не меняет её глобально. Учитывайте память на соединения сверх guard pool; файловый журнал самого хаба не имеет ротации. Режим bench отключает часть защитных лимитов и нужен только для контролируемого тестирования.

Приватный хаб работает с собственным отпечатком без сертификата проекта. При необходимости можно загрузить публичные `hub.cert`, `hub-list.bin` и `locations.txt`: GameHub проверяет их родной утилитой. Для locations нужен заголовок `serial N`, затем строки в формате официальной инструкции. Корневой секретный ключ проекта и операции выдачи сертификатов остаются у владельца проекта; они не нужны для запуска частного хаба.

## Сохранение ключа и перенос

`hub-sign.key` создаётся на сервере с правами `0600`. Он не передаётся браузеру, не входит в обычные игровые ZIP-копии и сохраняется дополнительно в зашифрованном хранилище профиля GameHub. Обычная переустановка бинарника сохраняет этот ключ. При восстановлении ZIP на том же профиле ключ восстанавливается из защищённой базы, бинарник устанавливается повторно.

Для переноса идентичности на другую VPS сохраните **всю приватную папку данных панели**, включая базу, ключ шифрования панели и игровые папки. По умолчанию это `/var/lib/gamehub`. Переносите её закрытым каналом при остановленной службе, сохраняйте владельца `gamehub` и права; никогда не публикуйте эту папку или архив в GitHub. HTTPS-сертификат панели также является частью приватных данных. При потере ключа NightCoop меняется публичный отпечаток, и игрокам нужно заново добавить адрес.

Проверка GameHub охватывает сборку, запуск и остановку родного Linux-хаба, параметры и защиту ключа. Совместная игра с подключёнными клиентами Cyberpunk не проверена. Исходная [инструкция NightCoop](https://github.com/Twenfys/nightcoop-hub/blob/6b694a6c86fd7c2b93743497ab3bd924553f25b8/tools/hub/docker/README.ru.md) остаётся источником особенностей протокола и клиентского мода.
